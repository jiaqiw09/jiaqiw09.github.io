# 工程图解讲义风（Infra Visual Note）

## 先定内容契约

1. 从一般约束出发，明确读者需要回答的技术问题。区分代数等价、浮点近似、实现取舍和实测结论。
2. 在起草前确定全篇符号、向量方向、玩具数字、并行组与 Rank 归属、工程算例或真实基准。适用项写入 Spec Bar。统一复用。通用、手算和工程规模需要并存时，用标签标明各自适用范围。无测量数据时，明确标为工程估算，列出假设和计算式。
3. 拆成按概念或阶段递进的大节。每节开头用 2–4 句自然段说明前提、矛盾和本节要验证的关系，紧接图解或工作台。用左右表达对照和同级设备，用上下表达阶段或时间，用中列对齐跨设备传输、接口与不变量。
4. 在同一个模块呈现动作、原因、带形状的公式或接口，以及可验算的数字或槽位。现有图重画时，先核对箭头的端点、方向、数量、线型和交叉，再逐个复现。保留原文技术结论和参数。

## 选择组件

| 内容 | 组件组合 |
| --- | --- |
| 所有文章 | 契约头 → 各节导语和对应图解 → 终局卡。主体超过 3 节时，在标题与 Spec Bar 之间放 Jump Bar |
| 技术原理和模型架构 | 核心直觉卡 → 带形状的算子流水线 → 工程数字账本。涉及分支或设备时，用空间位置标出关系 |
| 数学推导 | 双栏工作台 → 维度括注和手算小矩阵 → 相同结果 → 数字账本 |
| 分布式数据流 | 阶段泳道 → 槽位条和算子签名 → 反向数据流与工程边界 → 通信账本 |
| 协议、硬件拓扑或调用栈 | 编号流水线 → 算子或 API 契约 → 工程边界洞察条 |

按需选用组件。用[可运行 HTML 模板](assets/components.html)中对应的完整结构和类名，替换内容与锚点。引用[公共样式](../../../assets/infra-visual-note.css)作为唯一视觉基座。新笔记存放在 `notes/<slug>/index.html`，引用 `../../assets/infra-visual-note.css`。组件增补与样式变更集中写入公共样式并同步模板。正文 HTML 复用标准类名及槽宽、色调等已有修饰符。保留 CSS 相对路径便于离线阅读。在站点左栏登记新笔记时，更新外层目录；文章内页只放自己的标题、锚点和内容。

## 写技术细节

- 首次出现符号时解释其物理含义、下标和形状。逐次写出矩阵乘法的输入与输出形状。移动结合次序、外积递推、在线归一化和分片等价性都用同一组小整数逐步核对。
- 泳道按前向、通信、输出和反向展开。每行伪代码末尾写形状注释。写明各阶段 Rank 持有什么、用哪个通信组、scatter/gather 轴、每 Rank 的逻辑元素量，以及该量与物理链路流量的区别。按任务交代 padding/mask、跨片 Shift 标签、反向通信的转置或逆映射、梯度归约范围及 loss 是否重复计算。不适用的边界写明原因。
- 账本把 MAC 展开成 `m · k · n`，注明精度、元素个数、每元素字节数和 MB/GB 或 MiB/GiB 的换算。区分常驻、临时、预计算、稳态和峰值，比较时固定口径。优选方案用文字说明成立条件。
- 导语使用 15px/1.72 和 82ch 行宽。卡片、泳道内采用紧凑文字，章节和图解之间保留标准空隙。多栏模块和宽表按 780/820/860px 三种安全宽度选型。窄桌面窗口保持拓扑，模块内部横向滚动。打印展开宽图。

## 固定视觉约束

- 蓝用于常规持有状态与输入，绿用于恒等、优化与结果，琥珀用于边界与瓶颈，珊瑚红用于错误或高代价反例，紫只用于跨设备通信。每处颜色须有文字或位置标签。对等 Rank 同用浅蓝，依靠列位置和等宽编号辨认。
- 使用暖白纸底、白色模块、细线、浅填充、无衬线正文、等宽数字和数学衬线公式。保持内页纯净。禁止内页站点导航、悬浮侧栏、厚白纸外框、暗色反转、阴影和临时配色。
- 禁用 Emoji、手写 `<br>` 和文章内联样式。禁用远程字体、内嵌 Base64 字体包和依靠外部 JS 的数学渲染。用原生 HTML 表达公式、矩阵与箭头。保留静态、离线可读的交付形态。

## 交付验证

逐项执行[交付自检](references/checklist.md)。至少核对桌面直开、阅读器内嵌、窄桌面横向滚动及打印预览。保留尚未完成的实测项，交付时据实说明。
