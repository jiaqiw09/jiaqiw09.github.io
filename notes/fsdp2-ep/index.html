以 ep_size=2、topk=2 为例的 FSDP2 + EP 端到端数据流

前置说明 / 术语说明

  1. token：指一个 token 位置的隐藏状态向量，shape = [hidden_size]。
  2. 若一个样本序列长度为 S，则 Attention 输出 shape = [S, hidden_size]，MoE 输入就是这 S 个 token 向量。
  3. 每个 token 会被 router 分配到 topk 个 expert。
  4. Permute / Unpermute 操作的是这 S×topk 个向量在行维度上的重排。
  5. 关键前提：本例中，EP 组的两个 rank 持有不同的输入 token；AllToAll 负责把 token 发往对应 expert 所在 rank，并在计算后返还。

💡 注：4 卡、ep_size=2 时，EP group 可为 {卡0, 卡1} 与 {卡2, 卡3}；这里仅展示一个 EP group 内两张卡如何协作完成 MoE 计算。

为什么 EP 不改变 MoE 的数学结果

  • 对比条件：两种执行方式使用相同的输入、专家函数、路由结果和路由权重，保留相同的 token–expert 配对。
  • 发往专家：每条记录对应一个 token 的一个 top-k 槽位。重排和第一次 AllToAll 将记录送到对应专家所在的 rank。
  • 按专家计算：Grouped MatMul 批量执行各专家的矩阵乘法，配合相同的激活函数和逐元素运算，得到每条记录的专家输出。
  • 返还与合并：恢复发送分段后，第二次 AllToAll 将专家输出送回输入 rank，再按原 token 和 top-k 槽位对齐权重并求和。
专家输出：z[i,k] = expert[top_k_index[i,k]](token[i])
合并输出：output[i] = Σₖ top_k_weights[i,k] × z[i,k]

两种执行方式在数学上得到同一个式子。浮点实现可能因计算顺序或 kernel 不同而有舍入差异。

最终结论

Permute + AllToAll + Permute + Expert Compute + Unpermute + AllToAll + Unpermute 的整体流程，本质上只是：

1 把 token 送到对应 expert 所在 rank；2 让同一 expert 的 token 连续排列以便 GMM 计算；3 计算后再按相反顺序还原；4 在相同路由与专家函数下，得到与无 EP 相同的数学结果。

★ 通信只改变 token 的位置，Permute 只改变顺序，GMM 只改变执行方式，在相同路由和专家函数下，MoE 的加权求和公式保持一致。
