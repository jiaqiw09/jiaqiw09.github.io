以 ep_size=2、topk=2 为例的 FSDP2 + EP 端到端数据流

前置说明 / 术语说明

  1. token：指一个 token 位置的隐藏状态向量，shape = [hidden_size]。
  2. 若一个样本序列长度为 S，则 Attention 输出 shape = [S, hidden_size]，MoE 输入就是这 S 个 token 向量。
  3. 每个 token 会被 router 分配到 topk 个 expert。
  4. Permute / Unpermute 操作的是这 S×topk 个向量在行维度上的重排。
  5. 关键前提：在 FSDP2 + EP 架构下，EP group 内各 rank 属于不同的数据分片，因此看到的输入 token 不同；AllToAll 负责把 token 发往对应 expert 所在 rank，并在计算后返还。

💡 注：4 卡、ep_size=2 时，EP group 可为 {卡0, 卡1} 与 {卡2, 卡3}；这里仅展示一个 EP group 内两张卡如何协作完成 MoE 计算。

3.1 为什么数学上等价

  • 计算视角：每个 expert 做的仍然是 output = input @ weight；GMM 只是把多个 expert 的矩阵乘法批量在一起，数学上等价于逐个 expert 分别计算再拼接。
  • 通信视角：AllToAll 只改 token 所在 rank，不改变 token 内容。
  • 排列视角：Permute 只改变顺序，Unpermute 恢复原始顺序；排序不改变矩阵乘法的数学结果。
  • 加权视角：最后按 top_k_weights 对 topk 个 expert 输出加权求和，等价于无 EP 时的组合方式。
无 EP:  output[i] = Σₖ (top_k_weights[i,k] * expert[top_k_index[i,k]](token[i]))
有 EP:  output[i] = unpermute(GMM(permute(AllToAll(permute(tokens)))))[i]
        = Σₖ (top_k_weights[i,k] * expert[top_k_index[i,k]](token[i]))

最终结论

Permute + AllToAll + Permute + Expert Compute + Unpermute + AllToAll + Unpermute 的整体流程，本质上只是：

1 把 token 送到对应 expert 所在 rank；2 让同一 expert 的 token 连续排列以便 GMM 计算；3 计算后再按相反顺序还原；4 最终得到与无 EP 直接计算完全等价的结果。

★ 通信只改变 token 的位置，Permute 只改变顺序，GMM 只改变执行方式，不改变最终数学结果。
