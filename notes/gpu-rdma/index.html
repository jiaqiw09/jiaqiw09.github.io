01

双节点硬件拓扑与互联层级

拓扑把 GPU、CPU、网卡与交换芯片连成可追踪的路径。要判断一次搬运跨几级交换和 NUMA，先找每张卡所归属的 PCIe Root Complex。

01 主机与设备

CPU ↔ GPU

常见分立 GPU 使用 PCIe。GH200 的 Grace ↔ Hopper 可用 NVLink-C2C 实现一致性内存访问。

02 同机互联

同机 GPU ↔ GPU

可经 PCIe P2P、NVLink 直连或 NVSwitch。交换芯片按目标端口转发。

03 跨机互联

跨机 GPU ↔ GPU

本机 GPU ↔ NIC、IB/RoCE 网络、对端 NIC ↔ GPU 是三个可单独核对的区段。

共享带宽 ·同一 PCIe Switch 下的设备在支持时可直接 P2P。多个下行设备访问主机内存时，可能共用 Switch 上行链路。

02

RDMA Write 机制与五步硬件流水线

RDMA Write 从注册缓冲区开始，经过建连、提交、搬运和完成同步。按流水线分清哪些操作由 CPU 发起，哪些字节由设备直接搬运。

本地搬运

DMA · 本机

设备按命令读写本机内存。例如网卡从 DRAM DMA 读取待发数据。

跨机直连

RDMA · 跨机

网卡按对端授权读写已注册内存。InfiniBand 和 RoCE 都可承载 RDMA。

显存直达

GPUDirect RDMA · 显存

GPU 显存可被注册给网卡，网卡经本机 PCIe 直接读写，不需要显式在 Host DRAM 中转。

  1. 01

    注册缓冲区

    ibv_reg_mr()

    登记地址范围与权限，获得 Memory Region。

  2. 02

    建连交换 rkey

    ibv_create_qp()

    建立并配置 QP，交换远端地址和访问钥匙 rkey。

  3. 03

    提交写请求

    ibv_post_send()

    提供本地地址、lkey、长度、远端地址和 rkey。

  4. 04 网络传输

    网卡 DMA 搬运

    PCIe DMA → IB/RoCE

    源网卡 DMA 读，目标网卡校验后 DMA 写。

  5. 05 完成

    完成队列同步

    ibv_poll_cq()

    查询请求完成。接收端按协议确认可消费时机，并与 GPU stream 协调。

CPU 的角色 ·应用或通信库负责注册、提交与协调，Tensor 字节由设备搬运。普通 RDMA Write 需要额外协议通知接收端何时读取。

03

发送卡与接收卡之间保留同一条跨机 RDMA 链路。任一端失去 GPUDirect 能力时，该端路径可退到 Host DRAM 中转。

计量口径 ·一次 PCIe 数据传输指一次设备 ↔ CPU 或设备 ↔ 设备的数据移动，Switch 内部物理链路不重复计数。400 ÷ 8 = 50 GB/s 是线速上限，实际带宽受拓扑、MTU、协议和重叠影响。

04

NCCL 按连接选路逻辑

训练框架先划分 Rank 组，NCCL 再按拓扑和连接能力组织 channel。选路粒度是每条收发连接。

按连接选择

入口契约

selectTransport() → canConnect() → setup()

对每条收发连接判断可用能力，从上到下检查右侧条件。

01 P2P

P2P 可用

p2pCanConnect() → p2pSendSetup() / p2pRecvSetup()

GPU 通常经 NVLink 或 PCIe 直接互访。

02 SHM

P2P 未选中，SHM 可用

shmCanConnect() → shmSendSetup() / shmRecvSetup()

通过共享主机缓冲区交换。

03 NET IB/GDR/Socket

P2P 与 SHM 未选中，NET 可用

IB / RoCE 可分别判断发送端、接收端 GDR 能力。Socket 使用主机缓冲区。

按连接选 ·同一次 All-to-All 可在机内走 P2P，在跨机连接走 NET。专用传输和网络插件可能改写常见路径。
