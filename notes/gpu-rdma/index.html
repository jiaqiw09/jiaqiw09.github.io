硬件拓扑决定有哪些路可走

拓扑描述 GPU、CPU、网卡和交换芯片如何连接。沿着路径可以看出经过几级交换、是否跨 NUMA、哪些设备共用链路。下图是两台服务器的示意，每台只画出 CPU 0 下的 PCIe 设备。

CPU ↔ GPU

常见分立 GPU 经 PCIe。GH200 的 Grace ↔ Hopper 经 NVLink-C2C，支持一致性内存访问。

同机 GPU ↔ GPU

可经 PCIe P2P、NVLink 直连或 NVSwitch。交换芯片按目标端口转发。

跨机 GPU ↔ GPU

常见路径包含本机 GPU ↔ 网卡、IB / RoCE 网络、对端网卡 ↔ GPU 三段。

共享带宽　同一颗 PCIe Switch 下的 GPU 与网卡可以在支持时直接 P2P。多个下行设备同时访问主机内存时，可能共用 Switch 上行链路。

RDMA 让网卡直接访问远端缓冲区

一次 RDMA Write 从准备缓冲区开始，经过连接建立、提交、搬运和完成同步。沿着下面的流程核对哪些操作由 CPU 发起，哪些数据由设备搬运。

DMA · 本机

设备按命令读写本机内存。例如网卡用 DMA 从 DRAM 读取待发数据。

RDMA · 跨机

网卡执行读写请求，按对端授权访问已注册的内存。InfiniBand 和 RoCE 都可承载 RDMA。

GPUDirect RDMA · GPU 显存

通信库可以把 GPU 显存注册给网卡，网卡即可通过本机 PCIe 直接读取或写入它。

  1. 01 注册缓冲区

    ibv_reg_mr()

    注册地址范围和访问权限，得到内存区域（MR）。

  2. 02 建立连接

    ibv_create_qp()

    建立和配置队列对（QP），交换远端缓冲区地址和访问钥匙 rkey。

  3. 03 提交写请求

    ibv_post_send()

    提供本地地址、lkey、长度、远端地址和 rkey。

  4. 04 网卡搬数据

    PCIe DMA → IB / RoCE

    源网卡 DMA 读，经网络送到目标网卡。目标网卡校验权限后 DMA 写。

  5. 05 完成与同步

    ibv_poll_cq()

    查询请求完成。接收端按协议获知何时可以消费数据，并与 GPU stream 协调。

CPU 的角色　应用或通信库负责注册、提交与协调，Tensor 字节由设备搬运。普通 RDMA Write 需要协议配合，才能通知接收应用何时读取。

同一个跨机 Tensor 可以走不同路径

节点 A 的 GPU A0 发给节点 B 的 GPU B0。网卡之间保持 RDMA 时，两端仍可分别决定是否经过主机内存。

传输方式Tensor 数据路径主机内存中转
双端 GPUDirect RDMAGPU A0 → 网卡 A → IB/RoCE → 网卡 B → GPU B0无中转
仅发送端 GPUDirectGPU A0 → 网卡 A → IB/RoCE → 网卡 B → 主机 B → GPU B0接收端中转
仅接收端 GPUDirectGPU A0 → 主机 A → 网卡 A → IB/RoCE → 网卡 B → GPU B0发送端中转
RDMA 经主机内存GPU A0 → 主机 A → 网卡 A → IB/RoCE → 网卡 B → 主机 B → GPU B0双端中转
TCP SocketGPU A0 → 主机 A → TCP/IP → 主机 B → GPU B0双端中转

例子　双端 GDR 时，源网卡经本机 PCIe 读取 GPU A0 的显存，对端网卡经自己的 PCIe 路径写入 GPU B0 的显存。

NCCL 按连接选择传输

训练框架划分 rank 组。NCCL 根据拓扑和可用能力组织 channel，为每条收发连接设置传输。

按连接选　同一次 All-to-All 可以在机内连接上走 P2P，在跨机连接上走 NET。平台专用传输和网络插件可以改变具体路径。

从机器配置到实际验证

从 GPU 互访能力查到实际训练选用的网卡和传输。能测通主机内存上的 RDMA 后，再单独确认网卡能否直接访问显存。

检查项命令或工具核对内容
看硬件拓扑nvidia-smi topo -m、lspci -tv确认 GPU ↔ GPU、GPU ↔ NIC 的路径和 NUMA。
测同机 P2Pnvidia-smi topo -p2p p、nvbandwidth核对 P2P 能力，再实测 GPU 互访带宽。
测跨机 RDMArdma link、ibv_devinfo、ib_write_bw先测主机缓冲区，再用支持 CUDA 的 perftest 测 GPU 缓冲区。
复现训练通信NCCL_DEBUG=INFO NCCL_DEBUG_SUBSYS=INIT,NET,GRAPH核对网卡和传输，再用相同 GPU 分组的 NCCL Tests 实测。

配置归属　整机布线决定硬件拓扑。宿主机驱动和平台所需的 Fabric Manager / NVLSM 初始化互联。网卡驱动、IB / RoCE 网络以及 DMA-BUF 或 nvidia-peermem 支撑 GDR。
